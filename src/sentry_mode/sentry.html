    Telegram setup and delivery

    Use the numeric chat ID from a message update received by your bot, or a public channel @username. Your bot must have permission to send there. Use this app’s HTTPS address when entering the token. The token is saved privately on the node and is never returned to the browser; leaving it blank keeps the saved token.

    Enable Telegram in each rule that should notify you. Test mode works without credentials. Live sending requires both a token and chat ID. Messages use the rule’s confirmation, cooldown, and rearming settings. Failures appear in the event log with no automatic retry. Disarming cancels pending sends; a message already submitted may still arrive.

    Saved SSH commands

    Use a host or SSH alias already accessible from this node with key authentication. Commands run exactly as saved, without inserting detection data.

    SSH setup and stopping behavior

    First verify the remote host key and set up key-based access from the node’s normal user account. Sentry uses existing SSH configuration and known hosts. It never prompts for a password, accepts an unknown host key, or retries a failed command.

    Disarming stops pending actions and the local SSH process. A command already started on the remote machine may continue running.
